# Compact low-profile keyboard

An 84-key, photo-inspired 75% keyboard built for the Workstation reveal workstation. The supplied overhead and three-quarter references determine the 16-unit layout, staggered modifiers, full-height navigation column, arrow cluster, gray key groups, thin charcoal frame, and orange Escape key. There is no added branding.

## Deliverables

- `keyboard.blend`: editable linked keycaps, named objects, packed legend image, and a separate preview studio collection.
- `keyboard.glb`: production asset, also copied to `public/glbs/keyboard.glb`.
- `layout.py`: all 84 key positions, widths, labels, and color groups.
- `build_keyboard.py`: geometry, materials, export, and three studio renders.
- `build_legends.py`, `legends.png`, `legend-rects.json`: reproducible atlas and packing coordinates.
- `perspective.png`, `preview.png`, `side.png`: three-quarter, near-top, and low side inspection views.
- `verify_glb.py`, `verify_import.py`, `verify_scene.mjs`: GLB, Blender round-trip, and scene placement checks.
- `asset-report.json`, `import-validation.json`, `scene-validation.json`: measured validation results.
- `workstation.png` and `browser-validation.json`: final application capture and browser checks.
- `references/`: the three user-supplied images retained for future editing.

## Geometry and coordinates

Dimensions are **308 × 118 × 21.236 mm** (width × depth × maximum height). Units are meters, X points right, Y points up, and +Z points toward the typist. Export axis conversion is disabled, matching the CRT workflow. `Keyboard_ROOT` is centered at the bottom contact plane; four low pads touch Y=0. The case rises gently toward the rear.

Keycaps share mesh data by unit width and tone. The actual layout needs 1u, 1.25u, 1.5u, 1.75u, 2u, 2.25u, and a 6.25u spacebar. Other widths can be generated by the same function. Shallow dishes, small bevels, and custom top normals avoid the inflated appearance of smooth-shaded boxes. No switches, screws, internal assemblies, or text geometry are modeled.

The Blender file contains 91 mesh objects plus the root, excluding the studio. GLB export collapses repeated keys with `EXT_mesh_gpu_instancing`: 17 nodes, 16 unique meshes, and 16 draw primitives. It stores 7,298 unique triangles and renders **22,148 triangles including every instance**. Rotations and scales are applied. Key placement remains in translation attributes so the exporter can reuse geometry; baking translations into separate meshes would defeat instancing. Three.js's existing GLTF loader supports this extension directly.

## Materials and legends

Four shared PBR materials cover the satin chassis, graphite keycaps, orange Escape, and legends. Vertex colors vary the dark and lighter gray key groups without adding materials. The single embedded **1024 × 1024 RGBA PNG** contains 83 legends; the spacebar is intentionally blank. One joined, shallow decal mesh follows the dished key tops with a 35 µm offset. Alpha masking avoids transparent sorting and makes the texture portable in GLTF. The atlas is packed into the Blender file and the GLB; no external texture fetch is required.

The references use `ctrl`, `option`, the command symbol, and `fn`, which are retained along with the F-row/media icons, navigation labels, arrows, and standard ANSI legends. Label typography and tiny media symbols are approximations intended for workstation viewing distances.

## Rebuild

Run from the repository root with Blender on PATH and Python with Pillow installed:

```powershell
python assets/keyboard/build_legends.py
blender -b --python assets/keyboard/build_keyboard.py
blender -b --python assets/workstation-desk/build_desk.py
python assets/keyboard/verify_glb.py
blender -b --python assets/keyboard/verify_import.py
Copy-Item assets/keyboard/keyboard.glb public/glbs/keyboard.glb
Copy-Item assets/workstation-desk/workstation-desk.glb public/glbs/workstation-desk.glb
node assets/keyboard/verify_scene.mjs
```

The atlas generator defaults to Windows Arial; set `KEYBOARD_FONT` to a sans-serif TrueType font on another platform. The builder uses Blender 5.2.1 and can skip previews with `-- --no-render`. Studio lighting and cameras remain in the editable file and are excluded from export. Preview renders use neutral lighting and contain no lighting baked into the model's materials.

## Workstation integration

`WorkstationEnvironment.tsx` lives alongside the CRT in the existing animated surface group. Both use `getCRTReferenceFrame` to derive scale from `CRT_Screen` (352 mm wide), preserve the original screen alignment, and find the contact plane from `CRT_Stand`. The complete CRT's loose bounding box is deliberately not used: its badge contains unrelated outlying bounds, whereas the stand is the authoritative physical support.

The desk's top is at the CRT feet's measured Y=-0.280866 m. Its 950 × 900 × 28 mm source asset is scaled to 5.225 m wide and 1.26 m deep in the scene and centered at Z=-0.28 m. The width keeps its side edges outside the desktop framing. The keyboard is at X=8 mm, Z=170 mm with a -2° yaw. Both assets meet the contact plane exactly. Conservative bounds give **40.86 mm clearance** between keyboard and CRT, **421.17 mm behind the CRT**, and **115.66 mm in front of the keyboard** before the desk edge. A matte charcoal wall meets the rear edge at Z=-0.91 m and follows desk position/depth changes.

Defaults live in `CONFIG.workstation`; `/debug` exposes a separate Workstation folder for keyboard position/rotation/scale and desk position/scale. Positions are native asset meters, rotations are degrees, scales are multipliers. Keyboard Y is relative to the desk top; desk Y offsets the CRT's support plane. Moving the desk vertically or tilting the keyboard can intentionally break contact and should be checked visually.

The camera's final Y moves down 75 mm in asset coordinates to keep the keyboard visible. Its orientation, zoom timing, screen UV system, pointer raycasts, and return transition remain intact. A cached 512px contact shadow is captured in an isolated scene in asset coordinates when the workstation is revealed. This avoids scaled-camera issues and is independent of viewport size. It renders only once, or again after editing workstation controls; allocated targets and materials are disposed on unmount. The existing environment lighting remains; the photographic backdrop has been replaced by the wall. Wall dimensions and material settings live in `CONFIG.workstation`.

## Scope and limitations

This is a reference-matched real-time asset rather than a measured manufacturer replica. Subtle surface grain, switch internals, ports, and cables are omitted. Keycaps are static; no key-press interaction was requested. The tabletop intentionally has no legs. Studio renders support asset inspection; the application screenshot is the reference for the existing scene lighting and framing. GPU instancing must be supported by any downstream viewer, or the linked objects can be re-exported with `export_gpu_instances=False`.
